# Gaokao-Passage-Helper

一个面向高考作文的**素材生产工具**。输入一个主题词（如「苏轼」「陶渊明」「AI」），自动检索资料并产出一份结构化、可直接用于议论文的素材卡；另外提供一个小工具，把成品素材压成**考前速览版**，用于考前快速唤醒记忆。

---

## 一、它做什么

给一个主题词，输出一份包含以下字段的素材卡：

| 字段 | 含义 |
|---|---|
| `name` | 素材名称（人物名 / 事件名） |
| `tag` | 该素材可对应的作文主题标签 |
| `summary` | 精炼总结，用于考前速览快速唤醒记忆 |
| `detail` | 展开的细节、名言、小众但有力的视角；**每条自带 tag 标注** |
| `transcend` | 思辨点 / 深刻点，按深度排序，用于把议论写深 |
| `note` | 使用建议：适合放在议论文的什么位置、有哪些坑要避 |
| `cache` | 使用示例，覆盖多个角度，凝练深刻 |

设计目标不是「堆生平」，而是产出**有论证价值、有辨识度**的素材，并明确告诉你**该怎么用**。

如果只想考前快速过一遍，可以再用简化工具把素材卡压成速览版（见 5.3）。

---

## 二、工作原理

### 2.1 素材生成（两阶段）

流程分两阶段，分别走 DeepSeek 的两个不同接口：

```
主题词
  │
  ├─ 阶段 1：get_anthropic()
  │    Anthropic 兼容接口 https://api.deepseek.com/anthropic
  │    模型 deepseek-flash，开启 web_search 工具（max_uses=90）、effort=high
  │    作用：真的去检索资料，产出一份「分析态」的素材文本
  │    记录：思考内容 + 输出内容 → log/{主题词}.md
  │
  ├─ 阶段 2：get_openai()
  │    OpenAI 兼容接口 https://api.deepseek.com
  │    模型 deepseek-flash，JSON 模式，开启思考
  │    作用：把上一步的文本整理成 JSON
  │    记录：思考内容 + 原始 JSON → log/{主题词}.md（续写）
  │
  └─ parse_sucai()
       把 JSON 渲染成人类易读的纯文本 → 素材/{主题词}.txt
```

**关于阶段 2 的 `fake_mat_finder`**：整理 JSON 时，系统提示词故意换成一个**不含检索能力**的版本（措辞是「思考要求」而非「搜索要求」）。目的是让模型认为"资料已经拿到了，现在只做格式化"，从而**不再尝试检索、也不再质疑资料来源**，专心完成结构化输出。

### 2.2 简化素材（单阶段、流式）

简化不检索、不转 JSON，只把一份成品素材压成「考前速览」：

```
素材/{主题词}.txt
  │
  └─ simpler.py
       OpenAI 兼容接口 https://api.deepseek.com
       模型 deepseek-flash，流式输出，开启思考
       系统提示词 prompt.simpler
       作用：严格基于原文做摘要，帮助考前快速唤醒记忆
       表现：tk 窗口与终端同步显示思考内容和回答
       → 简化素材/{主题词}.txt
```

素材此时已经整理好，简化只做**压缩与记忆化**，不新增事实——`prompt.simpler` 里写死了「严格以输入的素材为准，不可以修改、臆想、编造、添加其他内容」。

## 三、目录结构

```
Gaokao-Passage/
├── src/
│   ├── tool.py            # 核心：API 调用、日志、JSON→文本渲染、文件工具
│   ├── prompt.py          # 提示词：mat_finder / fake_mat_finder / resformat / simpler
│   ├── main_single.py     # 入口：单个素材
│   ├── main_batch.py      # 入口：批量素材
│   └── simpler.py         # 入口：简化素材（tk 弹窗 + 流式显示）
├── requirements.txt
├── THIRD-PARTY-NOTICES.md
├── LICENSE                # AGPL-3.0
└── README.md
```

程序运行时会在 `src/` 下自动创建输出目录（成品素材、运行日志、简化素材），这些生成物不纳入版本管理，因此不在上面的树里。

## 四、环境准备

- Python 3.10+
- 可访问 `api.deepseek.com` 的网络环境
- 一个 DeepSeek API Key

### 安装依赖

```bash
pip install -r requirements.txt
```

`requirements.txt` 只有两项：`openai`、`anthropic`，并带最低版本约束。

> 注意：`tool.py` 用到了 `output_config={"effort": "high"}` 等较新的参数，**anthropic 包版本过低会直接报 `TypeError: unexpected keyword argument`**。若遇到此错误，请升级：`pip install -U anthropic`

### 配置 API Key

代码通过环境变量 `DEEPSEEK_API_KEY` 读取密钥：

```python
# tool.py
api_key=os.getenv('DEEPSEEK_API_KEY')
```

**Windows（Git Bash）**

```bash
export DEEPSEEK_API_KEY="sk-xxxxxxxxxxxxxxxx"
```

**Windows（PowerShell）**

```powershell
$env:DEEPSEEK_API_KEY="sk-xxxxxxxxxxxxxxxx"
```

**临时单次运行**

```bash
DEEPSEEK_API_KEY="sk-xxxx" python main_single.py
```



## 五、使用方法

> **重要：必须在 `src/` 目录下运行。**
> 脚本内部使用的是 `log/`、`素材/` 这类相对路径，且 `import prompt` 依赖 `src/` 在模块搜索路径中。在项目根目录或其它目录运行，会导致导入失败，或把输出写到错误的位置。

```bash
cd src
```

### 5.1 单个素材

```bash
python main_single.py
```

交互过程：

```
输入素材名：苏轼
```

回车即开始；若成品已存在，会先询问是否覆盖。完成后生成 `素材/苏轼.txt`。

### 5.2 批量素材

```bash
python main_batch.py
```

交互过程：

```
输入一组素材名，用空格分割：苏轼 陶渊明 杜甫
即将整理这些素材，确认请输入 y 回车
['苏轼', '陶渊明', '杜甫']
y
```

必须输入 `y`（不区分大小写）才会执行，其它任何输入都会直接退出。素材名之间用空白字符分隔，连续空格或 Tab 都可以。

逐个素材串行处理，每个素材都会完整走一遍两阶段流程。素材越多、耗时越长。已存在的成品会跳过或按你的选择覆盖；单个素材失败不会中断整批，最后会汇总失败列表。

### 5.3 简化素材

```bash
python simpler.py
```

运行后先弹出一个 tk 窗口：

- 列出 `素材/` 下的全部素材，默认只勾选**还没有简化版**的项；已有同名简化素材的项会标注「已有简化素材」，默认不勾选；
- 可以勾选「覆盖已存在的同名简化素材」；不勾时遇到已存在的简化素材会跳过，并在结果里提示；
- 点「开始简化」后窗口切到结果页，按勾选顺序逐个处理：思考内容灰色、回答黑色，实时滚动显示，终端同步打印；
- 底部是进度条与状态行；单个素材失败不会中断整批，结束后汇总成功 / 跳过 / 失败；
- 任务进行中点关闭会二次确认，未完成的素材不会保存。

输出写入 `简化素材/{主题词}.txt`，与源素材同名。简化默认使用 `deepseek-flash`，可用环境变量 `SIMPLER_MODEL`、`SIMPLER_BASE_URL` 覆盖。

## 六、输出说明

素材生成阶段每个素材会产生两个文件（成品卡与运行日志）；简化素材则是另一份独立输出。

### `素材/{主题词}.txt` — 成品素材卡

由 `parse_sucai()` 渲染，纯文本、无 Markdown 语法，形如：

```
苏轼

tags:
  旷达·逆境, 家国担当·实干, 民本·为民

summary:
 苏轼（1037—1101），字子瞻，号东坡居士……

detail:
1.乌台诗案的九死一生：……
tag: 旷达·逆境 生死观 亲情·手足

2.王安石一句话救他：……
tag: 人格·交友

transcend:
  - "残疾"的普遍化……

note:
  - 别把他当"身残志坚"的符号使用……

cache:
  - （逆境）苏轼的豁达不是天赐……
```

### `log/{主题词}.md` — 运行日志

追加写入，用 Markdown 章节组织，按「阶段」记录每次请求：

```
# 苏轼

> 运行日志 · 创建于 2026-10-31 10:00:00

## 阶段 1 · 检索与素材整理

> 记录时间：2026-10-31 10:00:00

### 思考内容
……

### 输出内容
……

## 阶段 2 · JSON 整理（第 1 次请求）

### 思考内容
……

### 输出内容

````json
{ …原始 JSON… }
````
```

用于排查「素材为什么是这样」。想核对某条信息是否真的来自检索、或想手动修正 JSON，看这个文件。阶段 2 的 JSON 解析失败等警告会以引用块（`> **[WARN]** …`）追加在同一个文件里；阶段 2 的 JSON 修正重试也会作为新的章节追加。单个模式还会额外生成 `log/{主题词}json.md`，单独留档原始 JSON。

### `简化素材/{主题词}.txt` — 考前速览版

由 `simpler.py` 生成，纯文本，内容由 `prompt.simpler` 决定，通常是几条速览要点 + 记忆钩子，形如：

```
史铁生 · 速览卡
- 生卒/籍贯：1951—2010，北京人
- 经历：21岁双腿瘫痪；后患尿毒症，每周透析三次
- 自嘲：“职业是生病，业余在写作”
- 代表作：《我与地坛》《病隙碎笔》《命若琴弦》
- 名句：“死是一件不必急于求成的事……”
记忆钩子：21瘫痪 → 每周3透析 → 3部代表作 → “死是必然降临的节日”
```

内容**不得超出原素材**，它只是帮你考前快速过一遍，不替代原素材卡。

## 七、提示词说明（`prompt.py`）

| 变量 | 用途 |
|---|---|
| `mat_finder` | 阶段 1 的系统提示词，**带检索**。规定角色、搜索方向、输出字段与质量底线 |
| `fake_mat_finder` | 阶段 2 的系统提示词，**不带检索**，结构与 `mat_finder` 基本一致，仅把「搜索要求」改为「思考要求」 |
| `resformat` | 阶段 2 的用户提示词，给出 JSON 格式示例 |
| `simpler` | 简化阶段的系统提示词，角色是「高考作文专家 + 记忆大师」，要求摘要、可适当使用记忆术，且严格以输入素材为准 |

想调整素材风格（比如更侧重名言、或更强调思辨），改这几个提示词即可，无需动代码。

## 八、常见问题

**Q：报 `ModuleNotFoundError: No module named 'prompt'`**
没有在 `src/` 目录下运行。先 `cd src`。

**Q：`log/` 里只有一个空文件，没有素材产出**
说明阶段 1 抛出了异常导致流程中断。查看终端报错信息，常见原因是 API Key 未设置或额度不足。

**Q：素材内容看起来像模型编的，不像真检索过**
本工具的检索依赖上游对 `web_search` 工具的**服务端代执行**能力，请确认所用接口确实支持该工具。核对方法是查看 `log/{主题词}.md` 中的思考内容是否出现真实检索痕迹。

**Q：重复运行同一主题词，会不会把内容越写越长？**
不会。写入前会检查 `素材/{主题词}.txt` 是否存在：单个模式会询问是否覆盖，批量模式会统一询问是否覆盖已存在的素材；确认覆盖后以覆盖模式（`mode="w"`）写入。选择不覆盖则跳过。

**Q：报 400 错误，提示 `max_tokens` 超限**
素材生成在 `tool.py` 中写死了 `max_tokens=100000`（`get_anthropic()` 与 `get_openai()` 各一处），简化脚本里是 `MAX_TOKENS = 32000`；若模型上限更低会报错，按需调小。

**Q：想换模型**
素材生成的模型名 `deepseek-flash` 在 `tool.py` 中出现两次（`get_anthropic()` 与 `get_openai()`），两处都要改；简化用 `simpler.py` 的 `MODEL`，可直接改，也可用环境变量 `SIMPLER_MODEL` 临时覆盖。

**Q：简化素材太简 / 太啰嗦**
改 `prompt.simpler` 即可，比如要求「固定 6 条要点、每条不超过 20 字」，不用动代码。

**Q：简化窗口没有内容或停在「准备简化」**
窗口只负责渲染，真正的报错在终端和结果区的红色 `[ERROR]` 行里。先确认终端无异常，再确认运行环境能打开图形界面（`tkinter` 是 Python 自带模块，无需额外安装）。

## 九、已知限制

- **必须在 `src/` 下运行**，路径与模块导入均为相对形式，未做绝对路径处理。
- **API 调用本身没有重试**。网络错误、限流等仍会让当前素材失败。批量模式下单个素材失败会记录到失败列表并继续处理后续素材，最后统一汇总；单个模式失败则直接抛出异常。
- **阶段 2 的 JSON 解析失败会自动修正**：把报错信息追加到对话中，要求模型重新输出，最多重试 2 次；仍失败则按解析失败文本写入成品。
- **阶段 2 直接取 `reasoning_content` 属性**，若接口未返回该字段会抛 `AttributeError`。
- **串行处理，无并发**。批量素材耗时较长；简化也是一个接一个处理。
- **简化依赖图形界面**：`simpler.py` 用 tkinter 弹窗，无显示环境（纯 SSH、无桌面容器）无法运行。
- **简化中途失败没有重试**：当前素材记为失败，已生成的文件不受影响；重新运行时默认会跳过已完成的素材。
